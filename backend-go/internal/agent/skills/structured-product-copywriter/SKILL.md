# 结构化产品推介文案生成

本技能帮你把一组结构化产品参数,转换成既能讲清结构、又有销售打动力的客户推介文案。核心价值:参数一个不漏、点位换算不出错、卖点组织得有逻辑,而不是平铺直叙地罗列数字。

> **运行环境说明:** 本技能运行在 business-workbench 的 Go agent 内,所有"取数/换算/出材料"步骤都通过 agent 的 **Go 工具**完成(不是 Python 脚本/Playwright)。下方每一步都标了要调用的工具名。客户可见的数字(点位、胜率)只来自工具,绝不编造。

## 第一步:核对 10 项必填参数,缺了就问

无论用户给的是哪种结构(雪球/降敲雪球/DCN/FCN/限亏等),这 10 项都是必填。先逐项核对,把缺的挑出来一次性问用户,不要挤牙膏式地问一个等回复再问下一个——客户体验很差。

| # | 字段 | 示例 |
|---|------|------|
| 1 | 标的 | 中证1000 / 沪深300 / 中证500 / 创业板指 / 个股名 |
| 2 | 期限 | 36M锁3M(36个月,前3个月锁仓) |
| 3 | 保证金 | 50%(不追保) |
| 4 | 期初敲出线 | 101% |
| 5 | 降敲 | 0.5%(每月) |
| 6 | 降落伞(敲入线) | 60% |
| 7 | 派息线 | 78% |
| 8 | 费后派息 | 1.39%(月票息) |
| 9 | 打款日截至 | 6月30日 |
| 10 | 入场时间 | 7月3号或6号 |

**字段不适用的处理**:不同结构字段集会略有不同(例如 FCN 没有敲出线、限亏雪球没有降落伞)。如果某字段对该结构确实不适用,让用户明确说"不适用",打印参数块时省略该行即可——但核对这一步不能省,要确认是"不适用"而不是"漏写了"。

**为什么要一次问全**:这些参数之间有联动(降敲节奏影响安全垫厚度、降落伞位置决定抗跌能力),零碎提问会让你失去对整体结构的判断,也让客户来回被打断。一次性收齐,你才能写出有整体感的文案。

## 第二步:取实时点位 + 胜率 + 历史底部

文案里的分析需要几项数据,这些不能凭记忆编。

- **当前标的点位**(如"中证1000当前8601点左右")——用于换算降落伞、敲出线的绝对点位。**调 `fetch_quote` 工具**(标的→实时点位,腾讯/新浪/东财 3 源兜底)。取到了就用真实值,不要用记忆里的旧点位;工具失败才回头问用户要点位——绝不能因为失败就编一个数字。
- **回测胜率**(如"历史回测胜率98.17%")——这是文案最有冲击力的卖点,必须真实。**调 `fetch_winrate` 工具**(chromedp 驱动通毓终端回测页,需服务端配置 `TONGYU_USER`/`TONGYU_PASS` + Chrome)。凭证从环境变量读,不写进技能文件。`fetch_winrate` 失败/无凭证/遇验证码/站点不可达时,返回 `[胜率待补]` 占位——用该占位继续生成,文末标注"胜率待补,请手动提供",绝不编一个胜率数字。用户主动给了胜率就直接用。
- **历史参考底部**(如"2025年4月关税战底部收盘价5437.45点")——用于和降落伞点位做安全垫对比,这是文案最有说服力的一环。这一项工具不取,必须用户给。用户给了就用;没给就用 `[历史底部待补]` 占位继续生成,不要因此停下问用户阻断流程,文末标注待补。

为什么当前点位和胜率可以自动取、历史底部却要问:当前点位是"现价",有公开实时行情,`fetch_quote` 能可靠拿到;胜率是回测算出来的,`fetch_winrate` 能跑(依赖登录态和表单交互,遇验证码/站点不可达就退回占位);历史底部涉及"取哪一段、哪个口径(收盘/盘中)",是分析判断,得用户定。三者来源不同,别图省事混着编。

## 第三步:做点位换算与分析(调 calc_points 工具)

收到当前点位后,做机械换算。**调 `calc_points` 工具**(传降落伞/期初敲出线/派息线百分比 + `current_price` 由 `fetch_quote` 拿到)——工具返回绝对点位 + 口语化"约点"。**禁止你自己在对话里做乘法或点位换算(哪怕看起来很简单),必须调用 `calc_points`。**

- 降落伞绝对点位 = 当前点位 × 降落伞%
- 期初敲出绝对点位 = 当前点位 × 期初敲出线%
- 派息触发绝对点位 = 当前点位 × 派息线%(如适用)

然后组织卖点判断(这是文案的"分析骨架",基于 calc_points 给的绝对点位 + 用户给的历史底部):

1. **安全垫厚度**:比较降落伞绝对点位 与 历史参考底部。降落伞点位低于历史底部 → 安全垫厚,最强卖点;高于 → 卖点弱化,文案要诚实弱化,不要硬吹。
2. **降敲节奏**:每月降敲 0.5% 意味着敲出线逐月下移,敲出概率随时间推移而提高。讲清"越往后越容易敲出"。
3. **杠杆放大**:保证金 50%(不追保)= 2 倍杠杆,且不追保意味着极端行情下不会被强制平仓追加,风险可控。讲清"放大收益空间 + 不追保的安心"。保证金 100%(1 倍)时不要写"2 倍/双倍",如实写无杠杆即可。
4. **票息吸引力**:费后月票息 × 权益/期限,换算成"每月稳到手多少"。客户对"每月到手的钱"比"年化"更有感。
5. **市场语境**:结合用户给的市场判断(上涨/震荡/下跌行情),点出该结构在当前行情下的适配性。

**诚实底线**:卖点判断必须基于真实参数和真实行情数据。降落伞点位没低于历史底部就别写"安全垫厚";市场是下跌行情就别写"上涨行情下兼顾安全"。

## 第四步:产出文案(长版 + 短版)

### 长版结构

```
🚀【 <安全垫/票息卖点>｜<标的> <倍数> <结构类型>】

<一句话副标题:降敲节奏 + 安全垫 + 胜率 + 费后月票息 + 行情适配点>

<一段正文:当前点位与波动 → 降落伞绝对点位与历史底部对比(安全垫) → 降敲好处 → 杠杆放大与不追保 → 一句定位总结>

标的：<标的>
期限：<期限>
保证金：<保证金>
期初敲出线：<期初敲出线>
降敲：<降敲>
降落伞：<降落伞>
派息线：<派息线>
费后派息：<费后派息>
打款日截至：<打款日截至>
入场时间：<入场时间>
```

### 短版结构

短版只保留参数块 + 打款日/入场时间,不要正文分析,用于客户快速浏览或转发:

```
标的：<标的>
期限：<期限>
保证金：<保证金>
期初敲出线：<期初敲出线>
降敲：<降敲>
降落伞：<降落伞>
派息线：<派息线>
费后派息：<费后派息>

打款日截至：<打款日截至>
入场时间：<入场时间>
```

(短版里"不适用"的字段同样省略。)

### 写作风格要点

- **标题用 emoji + 正向卖点提炼**,不要只写产品名,也不要用"…才有风险/才会…"这种条件句当标题(听着像在劝退)。客户先看卖点再看结构,标题要给客户一个"我能得到什么"的正向钩子。若安全垫薄(降落伞高于历史底),标题就走票息/降敲路线,别硬蹭安全垫。
- **副标题浓缩 5 个点**:降敲节奏、安全垫、胜率、费后月票息、行情适配。
- **正文用"先现状、后对比、再结论"**:先给当前点位和波动,再用降落伞 vs 历史底部做对比(最有说服力),最后落一句定位。
- **数字配人话**:每个数字后面跟一句"意味着什么"。8800×60%=5280 后面要接"低于关税战底5437.45点,要跌破2025年最恐慌时刻才会敲入"。
- **倍数/杠杆写进标题**,放大收益是客户最直接的兴趣点。但保证金 100%(1 倍)时不要写"2 倍/双倍",如实写无杠杆即可。
- **不追保单独点一句**,这是风险可控的关键信号。

## 参考示例(供对齐风格,不要照抄)

> 🚀【 收益安全垫双重加厚｜中证 1000 2 倍 DCN】
>
> 每月降敲 0.5%,60% 安全垫,历史回测胜率达98.17%,费后月票息 1.39%,当前上涨行情下既兼顾安全性又守住收益
>
> 中证1000当前点位在8800左右,近期波动较大。目前布局2倍DCN,60%的降落伞(5200点左右,低于2025年4月关税战底部收盘价:5437.45点)以及每月0.5%的降敲让您入场更加安心,同时2倍杠杆能放大收益空间,是当下既能抗波动,又能增强收益的非常理想的配置。

注意这个示例里"5200点左右"是 8800×60%=5280 的口语化近似——`calc_points` 工具会返回这种"约点"表达,你直接用工具返回值,不要自己再四舍五入。

### 可选:详版/合规版(仅在用户明确要"详版/合规版/尽调版/含风险揭示"时才出)

上面的长版+短版是默认的简短推介体,用于客户快速浏览和销售转发。如果用户要的是面向合规、尽调或机构客户的完整材料,在长版基础上追加以下三块(短版仍保留):

- **情景分析表**:列出敲出/未敲出未敲入/跌破派息线未敲入/击穿降落伞 等情景下的结果,每行注明对应绝对点位(用 `calc_points` 的换算)。
- **风险揭示**:逐条列出敲入风险、未敲出风险、流动性风险、市场风险,以及"历史回测胜率不代表未来"。结构化产品非保本,这一段不能省,否则推介材料不合规。
- **适合客群**:2-4 条,写清适合什么样的投资者。

## 第五步(可选):生成 Word 推介材料(调 build_docx 工具,上传飞书)

用户要"出材料""出 Word""出推介文档"时才做,默认不出。**调 `build_docx` 工具**——按 `references/docx-template.md` 的 10 章顺序组装一个 manifest(sections 数组,内联文案文本 + 图片 path/占位),工具会装配 `.docx` 并**上传到飞书 Drive「某年某月产品」文件夹**(find-or-create),返回飞书下载链接。**不存本地。**

manifest 的 section 类型:`heading`/`subheading`/`body`/`params`/`image`/`separator`/`link_list`。文案数字用 `fetch_quote`/`calc_points`/`fetch_winrate` 已算的真实值,`build_docx` 只装配不改数字。

图片来源:
- **管理人/产品公示图**:调 `screenshot_amac` 工具(传 AMAC 详情页 URL,见 `references/amac-manager.md`)。
- **产品点位卡(派息敲出观察点位表图)**:调 `screenshot_product_card` 工具(见 `references/product-position-card.md`)。
- **胜率结果截图**:目前无独立工具(可留 `image` 占位 `[图片待补:胜率结果截图]`,胜率数字本身由 `fetch_winrate` 取,已在正文章节)。
- **一页通 / 托管募集账户截图**:用户手动贴,留 `image` 占位(`build_docx` 对缺图自动插红字 `[图片待补:xxx]`,不报错)。

manifest 里图片 section 的 `path` 用 `screenshot_*` 工具返回的 path;缺图留占位即可。`build_docx` 失败(如飞书 token 过期)会返回 error,如实告知用户,不要回退本地。

## 最后自检

产出前过一遍:
- [ ] 10 项参数齐全(不适用的已确认并省略)
- [ ] 当前点位调了 `fetch_quote`(真实值,不是记忆/编造)
- [ ] 绝对点位调了 `calc_points`(没自己算小数)
- [ ] 降落伞点位 vs 历史底部的对比方向诚实(低于才吹安全垫;历史底部缺失用了 `[历史底部待补]` 占位)
- [ ] 胜率:调了 `fetch_winrate`;取不到用了 `[胜率待补]` 占位;没编数字
- [ ] 长版 + 短版都给了
- [ ] 标题是正向卖点、非条件句;保证金 100% 时没误写"2 倍/双倍"
- [ ] 行情判断与用户给的真实行情一致,没自作主张
- [ ] 详版(情景/风险/客群)只在用户要合规版时才追加
- [ ] 用户要 Word 材料时:manifest 按 10 章组装;`screenshot_amac`/`screenshot_product_card` 取了图(或留占位);`build_docx` 上传飞书返回了链接;一页通/托管等手动贴的留了占位
