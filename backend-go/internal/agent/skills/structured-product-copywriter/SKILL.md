# 结构化产品推介文案与材料流程

本技能运行在 business-workbench 的 Go agent 内。取数、点位换算、胜率回测、截图、飞书原生云文档创建都通过 agent 工具完成。客户可见数字必须来自工具或用户明确提供，不能编造。

## 1. 核对参数

先核对以下参数，缺少时一次性问清：

| # | 字段 | 示例 |
|---|---|---|
| 1 | 标的 | 中证1000 / 沪深300 / 中证500 / 创业板指 |
| 2 | 期限 | 36M锁3M |
| 3 | 保证金 | 50%（不追保） |
| 4 | 期初敲出线 | 101% |
| 5 | 降敲 | 0.5%（每月） |
| 6 | 降落伞/敲入线 | 60% |
| 7 | 派息线 | 78% |
| 8 | 费后派息 | 1.39%（月） |
| 9 | 打款日截至 | 6月30日 |
| 10 | 入场时间 | 7月3号或6号 |

如果某字段对当前结构确实不适用，可以省略，但要确认不是漏填。

## 2. 自动取数

- 当前点位：调用 `fetch_quote`。文案里的当前点位必须来自该工具或用户明确提供。
- 绝对点位：调用 `calc_points`，用当前点位换算降落伞、期初敲出线、派息线。不要在对话里手算替代工具。
- 胜率数据：调用 `fetch_winrate`。失败时用“胜率待补”占位并说明原因，不能编造。
- 产品点位卡：调用 `screenshot_product_card`，用于“产品派息与敲出观察点位表图片”。
- AMAC 公示图：调用 `screenshot_amac`，必须传详情页 URL，不要截搜索结果页。

历史底部参考如果用户没有给出，用 `[历史底部待补]` 占位，不要凭记忆补数。

## 3. 文案输出

默认输出长版和短版。

长版结构：

```text
【 <核心卖点>｜<标的> <倍数/结构名称>】

<一句话副标题：降敲节奏 + 安全垫 + 胜率 + 费后月票息 + 市场语境>

<一段正文：当前点位与行情 -> 降落伞绝对点位与历史底部对比 -> 降敲好处 -> 杠杆与不追保 -> 总结定位>

标的：...
期限：...
保证金：...
期初敲出线：...
降敲：...
降落伞：...
派息线：...
费后派息：...
打款日截至：...
入场时间：...
```

短版只保留基础结构、打款日和入场时间，不写正文分析。

写作要求：
- 标题必须放在文案最前面。
- 安全垫判断要基于 `calc_points` 和用户给出的历史底部。
- 保证金 50% 可表述为 2 倍杠杆；保证金 100% 不要写 2 倍。
- 不追保要单独点出，但不能写成无风险。

## 4. 飞书原生云文档

用户要“推介材料”“销售物料”“飞书文档”时，默认创建飞书原生 `/docx/` 云文档，调用 `create_docx_material`，不要调用 `build_docx`。

`build_docx` 只在用户明确要求 Word 文件、`.docx` 附件或下载 Word 时使用。

飞书原生云文档必须按 `references/docx-template.md` 的 11 个 H2 章节顺序组装。文档标题按“产品名称简写-结构名称”，例如“泰创纶哲CTA一期-2倍DCN”。文档放入当月文件夹；如果没有当月文件夹，工具会自动创建。

图片 section 的 `path` 使用 `screenshot_amac` 或 `screenshot_product_card` 返回的本地 path。缺图可留 image 占位，`create_docx_material` 会插入“图片待补”文本，不要改走本地 Word。

## 5. 自检

- 参数齐全，缺失项已一次性问清。
- 当前点位来自 `fetch_quote`。
- 绝对点位来自 `calc_points`。
- 胜率来自 `fetch_winrate` 或明确标注待补。
- 长版标题在最前面。
- 飞书材料调用 `create_docx_material`，不是 `build_docx`。
- 文档章节严格按 11 个 H2 顺序。
- AMAC 截图来自详情页。
